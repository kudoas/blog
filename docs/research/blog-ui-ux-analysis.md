## この文書が答える問い

参考ブログのレイアウト・デザイン・機能は、記事の選びやすさと読みやすさをどう支えているか。
その観点から、現在のブログで優先して改善する点を整理する。
比較の観測値、見やすさについての解釈、改善候補をこの文書にまとめる。
現行仕様の正本は実装と記事データであり、この文書は調査日時点の記録である。

## 調査方法と判断の限界

macOS の Chrome 156 を Playwright から操作し、公開サイトの一覧と代表記事を確認した。
PC は横幅 1440 CSS px、スマートフォン相当は横幅 390 CSS px とした。
スクリーンショット、DOM、computed style、検索とタブの操作を確認した。

代表記事は次の 2 件である。

- 参考: [Device Posture API と Viewport Segments API で折りたたみ端末の画面に対応する](https://azukiazusa.dev/blog/device-posture-viewport-segments/)
- 現在: [Error BoundaryをFunction Componentで扱う](https://blog.da1chi.net/posts/func-error-boundary/)

本文の数値は、この環境と記事での実測値である。全記事、全端末を代表する最適値ではない。
公開サイトのデプロイ SHA は特定していない。ローカルの最新 main と公開画面を照合した。
検索結果数や記事数、配色などは、調査後に変わる可能性がある。

利用者テスト、視線計測、離脱率、読了率、表示速度の比較は実施していない。
以降の「見やすい理由」は観察に基づく設計上の解釈であり、因果的な効果を実証したものではない。
記事数、更新頻度、内容の新しさの違いも、デザインの効果と分けて考える。

## 記事を選ぶための情報と配置

### タイトル・概要・タグが読む前の判断を助ける

**観測:** 参考ブログの一覧には、各記事の画像、日付、タイトル、概要、タグがある。
概要は最大 3 行に制限され、概要領域の高さも揃えている。
画像、タイトル、概要、タグがカード内の決まった位置に配置されている。

**解釈:** タイトルで関心を持ち、概要で記事の対象や扱う範囲を確認し、タグでテーマを照合できる。
同じ場所に同じ種類の情報があるため、記事間を比較しやすい。
イラストは内容説明に加え、記事を見分けたり記憶したりする手がかりにもなると考えられる。

**現在の課題:** 通常の一覧はタイトル・日付・掲載元・タグが中心で、記事概要を表示していない。
検索時はローカル記事の一致箇所を表示するが、これは通常一覧での内容紹介とは役割が異なる。
目的の記事を探すには簡潔だが、知らないテーマの記事に興味を持つ材料が少ない。
また、外部記事 13 件はすべてタグが空で、主要テーマをタグから探せない。
このタグの問題は既存の[issue #90](https://github.com/kudoas/blog/issues/90)に該当する。

実装とデータ: [ArticleList.tsx](../../src/components/ArticleList.tsx)、[external.yaml](../../content/external.yaml)。

### 一覧と本文で画面幅の使い方を変えている

**観測:** 参考ブログの一覧は、横幅 1440px で約 1248px の領域に 3 列のカードを配置する。
スマートフォンでは 1 列になる。本文は PC でも横幅を抑えている。
現在のブログは一覧と本文に共通の最大 800px の領域を使う。
PC の一覧では日付用の 100px と列間の 24px を確保し、その右にタイトルを配置する。

**解釈:** 参考ブログは、一覧では複数記事の比較、本文では文章への集中を優先している。
現在の統一レイアウトは整然としているが、各画面の目的に合わせて調整する余地がある。

**トレードオフ:** 参考ブログの大きな画像と余白は、スマートフォンでのスクロール量を増やす。
現在の一覧には、タイトルを次々に確認しやすい長所がある。
記事数 22 件の現在のブログに、画像付き 3 列カードをそのまま採用する必然性はない。
日付の専用列を見直し、概要を加えた 1 列一覧にする案も比較対象になる。

実装: [global.css](../../src/styles/global.css)の `.shell` と `.article-summary`。

## 本文の文字組みと視覚的な階層

### 少し大きい文字と抑えた行長が文章を追いやすくする

本文の通常段落を計測した結果は次のとおり。参考ブログの冒頭概要は別のスタイルなので除外した。

| 条件 | 参考ブログ | 現在のブログ |
| --- | ---: | ---: |
| PC・文字サイズ | 17px | 16px |
| PC・行の高さ | 34px | 32px |
| PC・段落幅 | 756px | 800px |
| スマートフォン・文字サイズ | 16px | 15px |
| スマートフォン・行の高さ | 30.4px | 30px |
| スマートフォン・段落幅 | 326px | 350px |

**解釈:** 参考ブログは文字が少し大きく、段落幅も抑えている。
一行を追い、次の行頭へ戻る動作がしやすい構成と考えられる。
現在も行間は十分にあり、主な調整対象は文字サイズと行長である。
大きくするだけではスクロール量やコードの横スクロールが増えるため、幅と組み合わせて比較する。

再計測では、同じ画面幅で通常段落を開発者ツールから選ぶ。
computed style の `font-size`/`line-height` と `getBoundingClientRect().width` を確認する。
冒頭概要、囲みの補足、引用、コードのスタイルを通常段落と混同しない。

### タイトル・本文・補足の強弱が明確である

**観測:** 参考ブログの一覧タイトルは PC・スマートフォンとも 20px。
現在の一覧タイトルは PC で 17px、スマートフォンで 16px である。
代表記事の大見出しは、参考ブログが PC で 48px、現在が 34px だった。

**解釈:** 大きさと太さの差によって、タイトル、本文、補足の順序を把握しやすい。
現在は一覧のタイトルと小さなメタ情報を中心に構成され、強調の段階が控えめである。
文字サイズだけでなく、太さ、概要、余白を一緒に調整したい。

### 色が情報の役割を分けている

**観測:** 参考ブログのライト表示は、近い無彩色で背景・カード・罫線をまとめている。
本文リンクは緑、補足欄は青、タグには薄い背景があり、役割が視覚的に分かれている。
現在のブログもライト・ダークを備え、本文、補足色、リンク色を定義している。

**解釈:** 装飾を増やすより、本文・補足・操作対象を見分けるために色を使うことが参考になる。
現在の青を基調とする配色を維持しながら、タグや注意事項の役割を明確にする方法が考えられる。
今回の比較から、特定の色やテーマが全利用者に優れるとは判断しない。

## 読書の途中と読了後を支える機能

| 参考ブログで確認した機能 | 利用者にとっての役割と解釈 | 現在のブログとの違い |
| --- | --- | --- |
| 共通ヘッダーの検索・⌘K | 記事の途中でも別の記事を探せる | 検索入力は記事一覧にある |
| PCの追従目次 | 現在地や記事構造を確認し、別の節へ移動できる | 目次は記事上部にあり、追従しない |
| コードのコピーボタン | サンプルを試す操作を短くする | 手動で選択・コピーする |
| 補足・注意の囲み | 本筋と前提・注意点を区別する | 引用のスタイルはあるが、補足の種類別の見せ方は整備されていない |
| 関連記事 | 読了時の関心を次の記事につなげる | コメント欄と一覧へのリンクはあるが、関連記事の提示はない |
| Markdown取得・共有 | 保存や再利用を助ける | 同等の専用操作はない |
| ブログ／ショートのタブ、多言語、理解度クイズ | 読み方や利用目的に合わせた入口を設ける | 発信方針や記事の性質に応じて検討する候補 |

検索モーダルをクリックと⌘K で開き、検索語の入力、結果件数の表示を確認した。
ブログ／ショートのタブは切り替え操作と選択状態を確認した。
追従目次は PC でスクロール中も右側に表示されることを確認した。
コピー、共有、Markdown 取得、多言語については導線の存在を確認し、処理の完遂までは検証していない。
これらの機能の存在だけで、読みやすさや回遊率への効果を保証するものではない。

実装: [記事ページ](../../src/pages/posts/[slug].astro)、[BaseLayout.astro](../../src/layouts/BaseLayout.astro)。

## 現在のブログの課題と改善の優先順位

優先度は、記事の選びやすさ・読みやすさへの影響からの暫定評価である。
以下は実装済みの仕様や着手決定ではなく、次に比較・検証する候補を示す。

| 優先度 | 課題 | 改善候補 |
| --- | --- | --- |
| 高 | 記事を開く前の判断材料が少ない | 一覧に短い概要を追加し、何が分かる記事かを伝える |
| 高 | 外部記事を主要テーマから探せない | 外部記事のタグを整備する。管理先は[#90](https://github.com/kudoas/blog/issues/90) |
| 高 | 本文がやや小さく、一行が長い | PC17px前後、スマートフォン16px前後を候補に、段落幅と併せて比較する |
| 中 | 一覧と本文に同じ最大幅を使う | 一覧での比較と本文への集中を別々に設計する |
| 中 | トップ画面でブログのテーマが伝わりにくい | 「記事」の近くに扱う分野や読者への価値を短く示す |
| 中 | 記事内から検索を始められない | 記事ページにも共通の検索入口を設ける |
| 中 | 長い記事の途中で章を移動しにくい | PCの追従目次を検討する。モバイルの初期折りたたみは改善済み |
| 中 | 読了後の次の記事を見つけにくい | 共通タグなどを使って関連する記事を少数提示する |
| 中 | コードを試す操作が手作業になる | コードのコピーボタンを追加する |

トップ画面のテーマ説明は、[site.ts](../../src/site.ts)の既存のサイト説明と整合させる。
掲載元の違いも保持し、外部記事が別サイトへ移動することを引き続き分かるようにする。

## 最初に比較する改善案と評価方法

最初の候補は「概要とタグのある一覧」と「本文の文字サイズ・幅の調整」とする。
既存の 1 列一覧を活かし、記事を選ぶ場面と読む場面を改善できるためである。
独立した変更として比較し、同時反映によって効果を分離できなくなることを避ける。

| 候補 | 目的・対象範囲 | 完了条件と比較方法 |
| --- | --- | --- |
| 概要とタグのある1列一覧 | ローカル・外部記事を開く前に内容とテーマを判断できるようにする。概要・タグのデータ整備が前提 | 同じ記事群で現行案と比較し、目的に合う記事を選んで理由を説明できるか確認する。長いタイトル・概要なしの記事・検索結果も確認する |
| 本文の文字サイズと幅 | 読む負担を抑える。記事URLや本文内容を維持する | 同じ文章・端末・画面幅で読み進めやすさを比較する。長い日本語段落、英単語、コード、表、画像、200%ズームを確認する |

比較時は案の提示順序の影響にも注意する。数値を記録する場合は、対象者、課題、端末、
計測区間、同時に変えた条件を明記する。少人数の感想や単発の時間差を因果的な効果と断定しない。
読了率や回遊率は記事内容にも左右されるため、それだけを成功条件にしない。
利用者が記事を適切に選べることと、文章・コードを無理なく扱えることを確認する。

画像付きカードは、その次の比較候補とする。
視覚的な個性や記事の見分けやすさを得られる一方、画像の制作・選定・代替テキスト、
読み込み容量、モバイルの表示密度への負担がある。
画像なしの概要付き一覧と、2 列などのカード案を比較してから判断する。

検索、追従目次、関連記事、コピー機能は、それぞれ独立した改善として扱う。
利用者の入口・出口の動作を確認し、既存の検索条件の復元、フォーカス、キーボード操作、
JavaScript 無効時の閲覧、ライト・ダーク表示を維持する。
表示変更を採用する場合は、変更前の比較画面と検証結果を PR に残し、
データ整備と表示変更を分けて戻せるか確認する。
