## 記事を選ぶための情報と配置

### タイトル・概要・タグが読む前の判断を助ける

**観測:** 参考ブログの一覧には、各記事の画像、日付、タイトル、概要、タグがある。
概要は最大 3 行に制限され、概要領域の高さも揃えている。
画像、タイトル、概要、タグがカード内の決まった位置に配置されている。

**解釈:** タイトルで関心を持ち、概要で記事の対象や扱う範囲を確認し、タグでテーマを照合できる。
同じ場所に同じ種類の情報があるため、記事間を比較しやすい。
イラストは内容説明に加え、記事を見分けたり記憶したりする手がかりにもなると考えられる。

**変更前の課題:** 通常の一覧に概要がなく、外部記事 13 件のタグが空だった。

**現行の状態:** [PR #104](https://github.com/kudoas/blog/pull/104)で全 22 記事に概要を表示した。
外部記事 13 件のタグと概要も整備し、Angular 関連 7 件をタグから探せるようになった。
概要は最大 3 行とし、本文検索で一致箇所がある場合は抜粋を優先する。
本文抜粋と通常一覧での内容紹介は、異なる役割として維持している。
[issue #90](https://github.com/kudoas/blog/issues/90)のタグ不足は解消したが、記事を選びやすくなったかは未計測である。

実装とデータ: [ArticleList.tsx](../../src/components/ArticleList.tsx)、[external.yaml](../../content/external.yaml)。

### 一覧と本文で画面幅の使い方を変えている

**観測:** 参考ブログの一覧は、横幅 1440px で約 1248px の領域に 3 列のカードを配置する。
スマートフォンでは 1 列になる。本文は PC でも横幅を抑えている。
現在のブログは一覧の最大幅 800px を維持し、記事部分を最大 756px に分離した。
スマートフォンの本文は最大 326px とし、利用できる幅がそれより狭ければ収まるようにしている。
PC の一覧では日付用の 100px と列間の 24px を確保し、その右にタイトルを配置する。

**解釈:** 参考ブログは、一覧では複数記事の比較、本文では文章への集中を優先している。
今回の実装で一覧と本文の幅は分離した。複数列への変更や日付列の見直しはまだ行っていない。

**トレードオフ:** 参考ブログの大きな画像と余白は、スマートフォンでのスクロール量を増やす。
現在も 1 列でタイトルを縦に確認できるが、概要追加後は同時に見渡せる件数が減った。
記事数 22 件の現在のブログに、画像付き 3 列カードをそのまま採用する必然性はない。
現在は概要を加えた 1 列一覧を採用している。日付列や概要の表示量は、走査性の評価に合わせて見直す候補になる。

実装: [global.css](../../src/styles/global.css)の `.shell` と `.article-summary`。

## 本文の文字組みと視覚的な階層

### 少し大きい文字と抑えた行長が文章を追いやすくする

本文の通常段落を計測した結果は次のとおり。参考ブログの冒頭概要は別のスタイルなので除外した。
変更前と現在の列は、後述する同じ代表記事・画面幅での再計測値である。

| 条件 | 参考ブログ（初回調査） | 変更前 | 現在の本番 |
| --- | ---: | ---: | ---: |
| PC・文字サイズ | 17px | 16px | 17px |
| PC・行の高さ | 34px | 32px | 34px |
| PC・段落幅 | 756px | 800px | 756px |

| スマートフォン・行の高さ | 30.4px | 30px | 30.4px |
| スマートフォン・段落幅 | 326px | 350px | 326px |

**解釈:** 参考ブログは文字が少し大きく、段落幅も抑えている。
一行を追い、次の行頭へ戻る動作がしやすい構成と考えられる。

コードの文字サイズは 13px のままだが、スマートフォンでは表示領域が狭まり、横に送る距離が増えた。

再計測では、同じ画面幅で通常段落を開発者ツールから選ぶ。
computed style の `font-size`/`line-height` と `getBoundingClientRect().width` を確認する。
冒頭概要、囲みの補足、引用、コードのスタイルを通常段落と混同しない。

### タイトル・本文・補足の強弱が明確である

**観測:** 参考ブログの一覧タイトルは PC・スマートフォンとも 20px。
現在の一覧タイトルは PC で 17px、スマートフォンで 16px である。
代表記事の大見出しは、参考ブログが PC で 48px、現在が 34px だった。

**解釈:** 大きさと太さの差によって、タイトル、本文、補足の順序を把握しやすい。
現在は一覧に概要を追加し、タイトル・概要・メタ情報という段階ができた。
タイトルのサイズや太さは維持している。強調の見直しは、概要追加後の情報密度と合わせて再検討する。

### 色が情報の役割を分けている

**観測:** 参考ブログのライト表示は、近い無彩色で背景・カード・罫線をまとめている。
本文リンクは緑、補足欄は青、タグには薄い背景があり、役割が視覚的に分かれている。
現在のブログもライト・ダークを備え、本文、補足色、リンク色を定義している。

**解釈:** 装飾を増やすより、本文・補足・操作対象を見分けるために色を使うことが参考になる。
現在の青を基調とする配色を維持しながら、タグや注意事項の役割を明確にする方法が考えられる。
今回の比較から、特定の色やテーマが全利用者に優れるとは判断しない。

## 次の比較方法と撤回の条件

最初に、現在の概要付き一覧を基準として、情報量と走査性を比較する。
記事の対象や内容の理解と、目的の記事の発見の両方を確認する。
タイトルの表示件数だけ増やして概要を読めなくすることを成功条件にしない。
本文も、文字サイズや幅そのものではなく、文章とコードを無理なく扱えるかで判断する。

比較には同じ記事群と課題を使い、端末・画面幅・提示順を揃えて記録する。
少人数の感想や単発の時間差を因果的な効果と断定しない。
記事の発見やコードの扱いが難しいという観測があれば、表示行数・余白・幅を調整する。
概要が判断に使われない場合も、表示を見直す。
調整しても目的を満たせなければ、表示変更の撤回を検討する。

概要の表示だけ戻す場合は ArticleList と CSS を戻し、記事のタグ・概要データを維持できる。
文字組みは PR #105 の CSS 変更を戻せば元の表示になる。
PR #104 全体を戻す場合は、新規タグページも取り下げることになるため影響を確認する。

画像付きカードは、情報密度の評価後に比較する候補とする。
画像の制作・選定・代替テキスト、読み込み容量、モバイルの表示密度も評価する。
検索、追従目次、関連記事、コピー機能は、それぞれ独立した改善として検討する。
既存の検索条件の復元、フォーカス、キーボード操作、JavaScript 無効時の閲覧、
ライト・ダーク表示を維持し、採否の根拠を記録する。
